The global command is `rig`. It starts or connects to the project-local runtime
installed by `@rigkit/sdk`, loads `rigkit/index.ts`, and runs core or
project-defined operations.

## Common workflows

If you're new to `rig`, these are the command sequences you'll run most often.

**Set up a project for the first time:**

```sh
mkdir website
cd website
rig init                   # write rigkit/index.ts and install the SDK
rig plan                   # see what will run
rig apply                  # run pending setup tasks, cache results
```

**Create and use a workspace:**

```sh
rig create dev              # create a workspace from cached state
rig run dev ssh             # run a project-defined operation
rig run dev open-cmux       # operations are defined in rigkit/index.ts
rig ls                      # list workspaces
rig rm dev                  # tear down a workspace
```

**Refresh setup after editing the config:**

```sh
rig plan                    # preview what will rerun
rig apply                   # rerun only stale tasks
```

**Force a rerun:**

```sh
rig cache dev explain           # explain cache decisions
rig cache dev invalidate <task> # mark one task stale
rig cache dev invalidate --all  # mark every task stale
rig cache dev clear --local     # delete local cache entries
```

## Agents and CI

Agents, CI jobs, and scripts should run Rigkit non-interactively:

```sh
rig --json init
rig plan --workflow dev --json
rig apply --workflow dev --json
rig create --workflow dev dev --json
rig run dev status --json
rig rm dev --yes --json
rig cache dev invalidate --all --yes --json
```

Use `--json` on commands that support it instead of scraping interactive output.
Use `--yes` only for commands that ask for confirmation: `rig rm` and
`rig cache <workflow> invalidate --all`. Non-interactive runs fail instead of
prompting, so pass `--workflow`, workspace names, and required operation inputs
explicitly.

When a config asks the host to run a local command, interactive terminals ask
for approval first. Set `RIGKIT_TRUST_HOST_COMMANDS=1` to skip that prompt in
trusted automation.

The rest of this page is a reference for every command and option.

## Global options

Global options are accepted anywhere on the command line. Put them before the
command for readability, and use double-dash long flags for consistency with
command options:

```sh
rig --chdir=examples/smoke plan
rig --chdir=examples/global-fragments apply --workflow api
rig --state=/tmp/rigkit-state.sqlite plan
rig --json plan --workflow dev
```

Options:

| Option | Description |
| --- | --- |
| `--chdir <dir>` | Switch to a directory before resolving `rigkit/index.ts`. |
| `--state <file>` | Use a specific local runtime state database. |
| `--json` | Print machine-readable JSON where supported. |

By default Rigkit searches upward from the current directory for
`rigkit/index.ts`.

## `rig init`

Initialize a project:

```sh
rig init
```

`rig init` writes `rigkit/index.ts` and adds the Rigkit packages plus `plan`
and `apply` scripts to `package.json`, creating it if needed. It fails if
`rigkit/index.ts` already exists. It does not write `.env` or ignore rules.

Options:

| Option | Description |
| --- | --- |
| `--package-manager <pm>` | Install with `bun`, `pnpm`, `npm`, or `skip`. Interactive terminals prompt when omitted. |
| `--no-install` | Write files without installing dependencies. |
| `--json` | Print JSON. Implies skipping installation. |

## `rig plan`

Show which workflow tasks are cached or pending:

```sh
rig plan
rig plan --workflow api
rig plan --all
rig plan --discover
rig plan --workflow api --json
```

Options:

| Option | Description |
| --- | --- |
| `--workflow <name>` | Select a workflow explicitly. Interactive terminals prompt when omitted; non-interactive JSON runs should pass it. |
| `--all` | Run against every discovered project. |
| `--discover` | Discover projects below the selected directory. |
| `--json` | Print JSON. |

`plan` does not run pending tasks or start provider auth flows. It reports the
graph state Rigkit would use for `apply`, plus provider checks such as missing
Freestyle authentication or the currently selected Freestyle team.

## `rig apply`

Run pending workflow tasks and write cached outputs:

```sh
rig apply
rig apply --workflow web
rig apply --all
rig apply --discover
rig apply --workflow web --json
```

Options are the same as `plan`, plus `--dry-run` to report what would run
without executing tasks.

## `rig create`

Create a named workspace from the selected workflow's final context:

```sh
rig create dev
rig create --workflow api review-123
rig create --workflow api dev --json
```

If the project has no workspace lifecycle, `create` is not available.
In multi-workflow projects, use `--workflow` when you need to choose a specific
workflow or when running non-interactively.

## `rig run`

Run a workspace operation:

```sh
rig run dev ssh
rig run dev open-cmux
rig run dev status --json
```

The first argument is the workspace name. The second is a
`.workspaceOperation(...)` id from the config.

Operations such as `ssh`, `open-cmux`, `open-vscode`, and `status` are defined
in `rigkit/index.ts`. The names and behavior vary by project. After `rig create`,
the CLI prints available next-step operations in interactive terminals. Use
completion or `rig run --help` for command syntax.

Project-defined Zod operation inputs become CLI flags. For example, an operation
declaring a `port` input becomes `--port`, and Zod enums complete as selectable
values. Use `--json` for machine-readable operation results.

## `rig rm`

Remove workspaces:

```sh
rig rm dev
rig rm dev --yes
rig rm --all --yes
rig rm --json
```

Options:

| Option | Description |
| --- | --- |
| `-y`, `--yes` | Skip confirmation. |
| `--all` | Remove every workspace in the selected project. |
| `--workflow <name>` | Select the workflow whose workspaces to remove. |
| `--json` | Print JSON. |

`rm` calls the workflow's `workspace.remove` hook before deleting the workspace
record.

## `rig ls`

List workspaces:

```sh
rig ls
rig ls --workflow api
rig ls --json
```

Additional list targets:

```sh
rig ls snapshots
rig ls config
```

`snapshots` lists cached snapshot runs. `config` shows resolved project paths.
The default workspace view is grouped by workflow and shows each workflow's
workspace list, cache status, and last applied summary when available.

## `rig cache`

Inspect and change workflow cache state. Cache commands require the workflow
name immediately after `cache`.

List cache entries:

```sh
rig cache dev ls
rig cache dev ls --json
```

Explain why each task is cached or pending:

```sh
rig cache dev explain
rig cache dev explain install-tooling
```

Invalidate cached task output so tasks rerun on the next plan/apply:

```sh
rig cache dev invalidate install-tooling
rig cache dev invalidate --all
rig cache dev invalidate --all --yes
```

Clear cache entries:

```sh
rig cache dev clear
rig cache dev clear --local
rig cache dev clear --global
```

Options:

| Option | Description |
| --- | --- |
| `--local` | Clear local cache entries for the workflow. |
| `--global` | Clear global fragments reachable from the selected workflow. |
| `--all` | With `invalidate`, mark every cached task in the workflow stale. |
| `--json` | Print JSON. |

Use invalidation when you want Rigkit to keep the cache records but mark them
stale. Use clear when you want to delete cache records.

## `rig providers`

Manage provider-owned local state.

Clear Freestyle browser auth, selected team, and provider identity state:

```sh
rig providers freestyle clear
rig providers freestyle clear --json
```

This does not load a project config or delete project `.rigkit` state. Clearing
provider-owned state changes the provider check fingerprint, so cached workflow
tasks that depended on that provider are treated as stale.

## `rig projects`

Discover Rigkit projects below the current or selected directory:

```sh
rig projects
rig --chdir=examples projects
rig projects --json
```

Discovery skips `.git`, `.rigkit`, `node_modules`, `dist`, and `build`.

## `rig doctor`

Show runtime diagnostics:

```sh
rig doctor
rig doctor --cli
rig doctor --json
```

Use `--cli` to show CLI diagnostics without connecting to a project runtime.

## `rig completion`

Generate shell completion:

```sh
eval "$(rig completion zsh)"
eval "$(rig completion bash)"
rig completion fish | source
```

Completion suggests commands, options, workspace names, and workspace
operations. If you installed Rigkit with the official installer, the installer
usually adds the completion hook to your shell profile for future terminal
sessions.

## `rig version` and `rig help`

```sh
rig version
rig help
rig run --help
```

`rig --version` and `rig -v` also print the CLI version.

## Environment variables

| Variable | Description |
| --- | --- |
| `RIGKIT_RENDER=0` | Force the plain text renderer instead of the interactive timeline. |
| `RIGKIT_DEBUG=1` | Show debug log lines from tasks and providers. |
| `RIGKIT_NO_CONSOLE_INTERCEPT=1` | Disable task console interception and write directly to the host terminal. |
| `RIGKIT_NO_BROWSER=1` | Print interaction URLs instead of opening a browser. |
| `RIGKIT_TRUST_HOST_COMMANDS=1` | Skip the approval prompt for config-requested local commands. |
| `RIGKIT_HOME` | Rigkit home directory. Defaults to `~/.rigkit` and holds global fragment state. |
| `RIGKIT_HOST_STORAGE_DIR` | Provider host storage directory. Defaults to `~/.rigkit/providers`. |
| `FREESTYLE_API_KEY` | Freestyle API key, read only by configs that pass `env.secret("FREESTYLE_API_KEY")`. |
| `FREESTYLE_TEAM_ID` | Select a Freestyle team without prompting during browser auth. |

Project `.env` files are loaded from the selected project directory.

## Exit behavior

Rigkit exits non-zero when:

- config loading fails;
- provider startup fails;
- a task, workspace hook, or operation throws;
- operation input validation fails;
- a selected workspace or operation does not exist.

For automation, prefer the [Agents and CI](#agents-and-ci) forms above.
