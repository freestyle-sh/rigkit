Providers connect `rigkit/index.ts` to external systems: VMs, terminals, editors,
cloud CLIs, local tools, and host capabilities.

Most configs just add providers and call their runtime helpers:

```ts
import { workflow } from "@rigkit/sdk";
import { cmux } from "@rigkit/provider-cmux";
import { freestyle } from "@rigkit/provider-freestyle";

const app = workflow("website");
const freestyleProvider = freestyle.provider();

export const website = app
  .sequence("website")
  .addProvider("freestyle", freestyleProvider)
  .addProvider("terminal", freestyle.terminal())
  .task("prepare", async ({ providers }) => {
    const { vm, vmId } = await providers.freestyle.client.vms.create({
      // A Freestyle VM reaches nothing it has not been allowed to.
      firewall: {
        rules: [{ action: "allow", source: {}, destination: { public: true } }],
      },
    });
    // ...
  })
  .addProvider("cmux", cmux.provider())
  .workspaceOperation("open-cmux", {
    title: "Open cmux",
    run: async ({ providers, workspace }) => {
      const cmuxWorkspace = await providers.cmux.ssh({
        ...(await providers.freestyle.cmux.createSshOptions({
          vmId: workspace.ctx.vmId,
        })),
        name: workspace.name,
      });
      await providers.cmux.selectWorkspace(cmuxWorkspace.workspaceId);
    },
  });
```

## Built-in providers

| Provider | Package | Use it for |
| --- | --- | --- |
| [Freestyle](/providers/freestyle) | `@rigkit/provider-freestyle` | VMs, snapshots, SSH, cmux adapters, VS Code URLs. |
| [Terminal](/providers/terminal) | `@rigkit/provider-freestyle` | Browser terminal sessions for login, SSH, and manual setup. |
| [cmux](/providers/cmux) | `@rigkit/provider-cmux` | Opening local cmux workspaces from `rig run`. |
| [Portless](/providers/portless) | `@rigkit/provider-portless` | Stable, named development URLs without app port numbers. |
| [gcloud](/providers/gcloud) | `@rigkit/provider-gcloud-cli` | Copying local `gcloud` auth/config files into a workspace. |

Need a provider for an internal system? See
[Creating providers](/providers/creating-providers).

## Provider config

Provider config can read environment variables through `env(...)`:

```ts
import { env, workflow } from "@rigkit/sdk";
import { freestyle } from "@rigkit/provider-freestyle";

const app = workflow("website");
const freestyleProvider = freestyle.provider({
  apiKey: env.secret("FREESTYLE_API_KEY"),
});

export const website = app
  .sequence("website")
  .addProvider("freestyle", freestyleProvider);
```

Rigkit loads `.env` from the selected project directory before loading
`rigkit/index.ts`. Resolved provider config is part of the scoped provider
fingerprint for tasks, workspace hooks, and operations after `.addProvider(...)`.
Changing provider config only makes cached runs stale where that provider is in
scope.

## What providers own

Providers are responsible for:

- resolving config and authentication;
- creating typed runtime helpers for tasks, workspace hooks, and operations;
- storing provider implementation records;
- storing developer-machine credentials in host storage when needed;
- validating cached artifact refs when remote resources may disappear;
- requesting trusted host actions such as opening URLs or cmux workspaces.

Task context should still stay simple: return durable JSON such as `snapshotId`,
`vmId`, `repoPath`, `devPort`, or provider artifact refs shaped like
`{ provider, kind, ... }`.

See [Cache and state](/concepts/cache-and-state) for where task context,
workspace context, provider storage, host storage, and global fragments live.
