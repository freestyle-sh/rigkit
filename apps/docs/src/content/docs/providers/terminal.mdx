The Freestyle terminal provider opens browser terminal sessions that connect to
Freestyle VMs over provider-owned SSH. It is useful for setup steps that need a
human to complete an interactive flow, and for workspace operations that should
drop a user into a shell.

## Add the provider

```ts
import { workflow } from "@rigkit/sdk";
import { freestyle } from "@rigkit/provider-freestyle";

const app = workflow("website");
const freestyleProvider = freestyle.provider();

export const website = app
  .sequence("website")
  .addProvider("freestyle", freestyleProvider)
  .addProvider("terminal", freestyle.terminal());
```

The terminal provider is separate from `freestyle.provider()` so configs can
use Freestyle VMs without enabling interactive terminal sessions.

## Open an interactive setup session

```ts
.task("github-auth", async ({ providers, step }) => {
  const { vm, vmId } = await providers.freestyle.client.vms.create({
    // A Freestyle VM reaches nothing it has not been allowed to.
    firewall: {
      rules: [{ action: "allow", source: {}, destination: { public: true } }],
    },
    snapshotId: step.ctx.snapshotId,
  });

  try {
    await providers.terminal.open("Log in to GitHub", {
      ssh: await providers.freestyle.createSSHOptions({ vmId }),
      command: "gh auth login --hostname github.com --git-protocol https --web",
      keepOpenAfterCommand: true,
      instructions: "Complete login, then type exit.",
    });

    const snapshot = await vm.snapshot();
    return { ctx: { ...step.ctx, snapshotId: snapshot.snapshotId } };
  } finally {
    await providers.freestyle.client.vms.delete(vmId);
  }
});
```

`keepOpenAfterCommand: true` keeps the shell open after the command succeeds,
which gives the user a chance to inspect state and type `exit` when ready.

## Open a workspace shell

```ts
.workspaceOperation("ssh", {
  title: "SSH",
  description: "Open an interactive shell",
  run: async ({ providers, workspace }) => {
    await providers.terminal.open(`SSH ${workspace.name}`, {
      ssh: await providers.freestyle.createSSHOptions({
        vmId: workspace.ctx.vmId,
      }),
      command: `cd ${workspace.ctx.repoPath} && exec bash -l`,
      keepOpenAfterCommand: true,
      instructions: "Exit the SSH session when you are done.",
    });
  },
});
```

## When to use it

- GitHub CLI device or browser login.
- Agent CLI initialization such as Codex or Claude.
- Manual one-time setup that should become part of a snapshot.
- Workspace SSH operations for humans.

For repeatable non-interactive commands, prefer `vm.exec(...)` in a task.
