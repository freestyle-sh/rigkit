The Freestyle provider gives Rigkit configs an authenticated Freestyle SDK
client plus helpers for SSH, cmux, and VS Code.

## Add the provider

```ts
import { workflow } from "@rigkit/sdk";
import { freestyle } from "@rigkit/provider-freestyle";

const app = workflow("website");
const freestyleProvider = freestyle.provider();

export const website = app
  .sequence("website")
  .addProvider("freestyle", freestyleProvider);
```

Default auth opens Freestyle browser login and stores credentials in
provider-owned host storage, outside project `.rigkit/state.sqlite`.
If the account belongs to multiple teams, Rigkit prompts for the team and
reuses that selection on later runs. `rig plan` shows Freestyle provider checks,
including missing auth or the active team, without starting OAuth.

To clear browser auth, selected team, and provider identity state:

```sh
rig providers freestyle clear
```

Clearing this state changes the provider check fingerprint and makes cached
Freestyle-dependent tasks stale.

For API-key auth:

```ts
import { env } from "@rigkit/sdk";

freestyle.provider({
  apiKey: env.secret("FREESTYLE_API_KEY"),
  teamId: env("FREESTYLE_TEAM_ID"),
});
```

`freestyle.provider(env.secret("FREESTYLE_API_KEY"))` is also supported.

## Prepare a snapshot

```ts
const setup = app
  .sequence("setup")
  .addProvider("freestyle", freestyleProvider)
  .task("install-dependencies", async ({ providers }) => {
    const { vm, vmId } = await providers.freestyle.client.vms.create({
      // A Freestyle VM reaches nothing it has not been allowed to.
      firewall: {
        rules: [{ action: "allow", source: {}, destination: { public: true } }],
      },
      idleTimeoutSeconds: 3600,
    });
    // Resources come from the snapshot; resize is grow-only.
    await vm.resize({ cpu: 4, memory: 16 * 1024, storage: 24 * 1024 });

    try {
      // Commands run as the image's uid 1000 user unless told otherwise; see
      // "Linux user" below.
      const install = await vm.linuxUser("root").exec({
        command: "corepack enable",
        timeoutMs: 60 * 1000,
      });
      if ((install.statusCode ?? 0) !== 0) {
        throw new Error(`Dependency install failed:\n${install.stderr}`);
      }

      const snapshot = await vm.snapshot();
      return { ctx: { snapshotId: snapshot.snapshotId } };
    } finally {
      await providers.freestyle.client.vms.delete(vmId);
    }
  });
```

Rigkit streams task console output to the CLI.

## Long-running commands

Freestyle caps a single `exec` at five minutes. For installs and builds that
can run longer, `execLongCommand` starts the command detached in the guest and
polls until it finishes:

```ts
import { execLongCommand } from "@rigkit/provider-freestyle";

const result = await execLongCommand(vm.linuxUser("root"), {
  command: "pnpm install --frozen-lockfile",
  timeoutMs: 20 * 60 * 1000,
  onOutput: (chunk) => console.log(chunk.trimEnd()),
});
if (result.timedOut || (result.statusCode ?? 0) !== 0) {
  throw new Error(`Install failed:\n${result.stdout}`);
}
```

## Linux user

`vm.exec(...)`, `pty`, and terminal sessions run as the VM's default user: the
account holding uid 1000 (`ubuntu` on the Freestyle base image), or `root` in
an image with no such account. That user has passwordless `sudo`, but it cannot
write `/root`, `/workspace`, or system paths directly.

Pick one user for a setup and use it everywhere, so files written during setup
are readable by later tasks, terminals, and editors. To run as root:

```ts
const root = vm.linuxUser("root");
await root.exec("apt-get install -y gh");

await providers.freestyle.terminal.open("Log in to GitHub", {
  vmId,
  linuxUser: "root",
  command: "gh auth login --web",
});
```

`providers.freestyle.terminal.open` runs over the VM's PTY and takes
`linuxUser`. The separate [terminal provider](/providers/terminal) connects over
SSH instead, so pass `user` through `createSSHOptions`:

```ts
await providers.terminal.open("Log in to GitHub", {
  ssh: await providers.freestyle.createSSHOptions({ vmId, user: "root" }),
  command: "gh auth login --web",
  keepOpenAfterCommand: true,
});
```

`createSSHOptions`, `cmux.createSshOptions`, and `vscode.createUrl` accept a
`user` option and default to `root`.

## Create workspace VMs

```ts
.workspace({
  create: async ({ workflow, providers }) => {
    const { vmId } = await providers.freestyle.client.vms.create({
      snapshotId: workflow.ctx.snapshotId,
      firewall: {
        rules: [{ action: "allow", source: {}, destination: { public: true } }],
      },
      idleTimeoutSeconds: 3600,
    });

    return { vmId };
  },
  remove: async ({ providers, workspace }) => {
    await providers.freestyle.client.vms.delete(workspace.ctx.vmId);
  },
});
```

Return `snapshotId` from setup tasks and `vmId` from workspace creates. Those
ids are durable JSON values Rigkit can cache and reload.

## SSH helpers

Create SSH options when another provider or host action needs to connect to the
VM:

```ts
const ssh = await providers.freestyle.createSSHOptions({
  vmId: workspace.ctx.vmId,
});
```

The provider grants SSH access for the active Freestyle identity and returns a
provider-owned token connection. Project code does not manage SSH keys.

## cmux and VS Code

```ts
const cmuxWorkspace = await providers.cmux.ssh({
  ...(await providers.freestyle.cmux.createSshOptions({
    vmId: workspace.ctx.vmId,
  })),
  name: workspace.name,
});
await providers.cmux.selectWorkspace(cmuxWorkspace.workspaceId);
```

```ts
const url = await providers.freestyle.vscode.createUrl({
  vmId: workspace.ctx.vmId,
  cwd: workspace.ctx.repoPath,
});

await local.open(url);
```

## Exports

`@rigkit/provider-freestyle` exports the provider helpers and Freestyle SDK
types commonly used by configs:

```ts
import {
  execLongCommand,
  freestyle,
  Freestyle,
  type FirewallSpec,
  type FreestyleSdkVm,
} from "@rigkit/provider-freestyle";
```

The `freestyle` SDK package is a peer dependency, so it must be installed
alongside the provider.

## Patterns

- Create temporary VMs in setup tasks, snapshot them, and delete them in
  `finally`.
- Install VM dependencies with `vm.exec(...)` inside setup tasks before
  snapshotting.
- Store IDs, paths, ports, branch names, and commands in JSON context.
- Use the terminal provider for interactive auth flows.
- Set `idleTimeoutSeconds` deliberately for both setup and workspace VMs.
